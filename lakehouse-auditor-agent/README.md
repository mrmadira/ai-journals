# Lakehouse Audit Agent (`audit-lake`)

An autonomous agent that audits watsonx.data on a schedule and **proposes** fixes for a human to
approve. It's the standalone version of the `lakehouse-audit` skill.

## How it works

| Step | Who | What |
|---|---|---|
| Pre-flight | code | Lists engines and measures idle time **before** the model starts. Presto: fixed SQL on `system.runtime.queries`, ignoring SHOW/DESCRIBE/EXPLAIN and itself. Spark: time since the last application ended (server-side history) |
| Investigate | model | Read-only tools only: inventory, catalog probes, Spark apps, analysis |
| Propose | model → code | `propose_action` → code validates against measured facts → `state/proposals.json` |
| Report | code | Writes `audits/agent-audit-<date>-<time>.md` (redacted again, proposal table generated by code) |
| Approve | **you** | `audit-lake review` / `approve <id>` |
| Execute | code | Re-checks *now* (still running? still idle? no active apps?), then pauses. Never `force`. |

The model never sees `execute-select` or any pause/create/update/delete tool.

## Commands

```bash
./audit-lake run                         # unattended audit (exit 0 clean, 2 needs you, 1 failed)
./audit-lake status                      # pending proposals + latest report
./audit-lake review [--dry-run]          # interactive approve / reject
./audit-lake approve <id> [--dry-run] [--confirm <engine_id>]   # --confirm needed for donotdelete engines
./audit-lake reject <id> --note "why"    # snoozes that proposal for 7 days
```

## Guardrails (all enforced in code: `guardrails.py`, `state.py`)

- Read-only tool allowlist; no SQL tool for the model
- Secrets redacted from every tool result **before** the model or logs see them (fingerprints kept,
  so shared credentials are still detectable)
- Proposals checked against facts: right engine type, running, idle ≥ `AUDIT_MIN_IDLE_HOURS`,
  0 active Spark apps (verified by code, not taken from the model)
- Proposals expire after 24h (stale evidence); rejections snooze for 7 days; max 5 per run
- Protected (`donotdelete`) engines need the engine id typed to approve
- Last real activity per engine is remembered in `state/activity.json`, so idle time survives
  Presto's ~100-query history wrapping (the audit's own probes push old queries out) or a restart;
  such measurements are marked confidence **medium (saved)**
- Idle ≥ `AUDIT_HIGH_IDLE_HOURS` (24) is HIGH, ≥ `AUDIT_MIN_IDLE_HOURS` (2) is LOW, decided in code
- Run lock (no overlapping runs), step / token / wall-clock limits, one retry for gateway 5xx
- Full JSONL trail in `logs/`

## Setup

Same `.mcp.json` and credentials as the analyst (`WXD_AUTH`, `AWS_BEARER_TOKEN_BEDROCK`, `AWS_REGION`).
For scheduled runs, put `WXD_AUTH=...` in `~/.config/audit-lake/env` (`chmod 600`); launchd doesn't
see your shell exports. Then schedule `audit-lake run` with launchd or cron (e.g. weekdays 07:00), with
`AUDIT_NOTIFY=macos` for a desktop notification. Reports go to `audits/` at the repo root.

Tune with env vars: `AUDIT_MIN_IDLE_HOURS` (2), `AUDIT_PROPOSAL_TTL_HOURS` (24), `AUDIT_SNOOZE_DAYS` (7),
`AUDIT_MAX_STEPS` (60), `AUDIT_RUN_TIMEOUT_S` (1500), `AUDIT_MAX_INPUT_TOKENS` (3M).
